# Build 36 Acceptance Tests

- [ ] Tickets are tenant-scoped.
- [ ] Priority and severity are distinct.
- [ ] Ticket transitions are auditable.
- [ ] SLA clocks use explicit policies and calendars.
- [ ] Waiting/pause states follow policy.
- [ ] Escalation can be deduplicated.
- [ ] Customer-visible replies are distinct from internal notes.
- [ ] Delivery status comes from provider evidence.
- [ ] Resolution must be verified before closure.
- [ ] Tickets can reference Build 22 incidents.
- [ ] Security concerns route to restricted Build 21 handling.
- [ ] Knowledge articles are versioned and reviewed.
- [ ] Sensitive data and secrets are minimized.
- [ ] Reopened tickets preserve prior history.
