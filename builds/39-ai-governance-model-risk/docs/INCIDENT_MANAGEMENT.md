# AI Incident Management

Incident records should capture:
- affected deployment/use case
- severity and category
- detection source
- scope and impact assessment
- containment and communication decisions
- evidence and timeline
- root-cause analysis
- corrective action
- retest and reopening criteria
- accountable reviewer

Security incidents also route through Build 21. Reliability incidents may link to Build 22. Trust/audit events should link to Build 20. Avoid copying sensitive payloads into general incident notes.
